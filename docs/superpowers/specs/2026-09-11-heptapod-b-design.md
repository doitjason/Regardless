# 헵타포드 B 로고그램 생성기 — 설계 문서

- 작성일: 2026-09-11
- 성격: 비영리 팬 창작 프로젝트
- 목적물: 한국어·영어 입력을 헵타포드 B 양식의 로고그램으로 변환하는 웹앱, 그리고 그 출력으로 제작하는 목걸이 각인 파일

---

## 1. 프로젝트 목적

영화 《컨택트》(원제 *Arrival*, 2016)의 외계 문자 **헵타포드 B**를 팬 창작으로 체계화하고, 누구나 쓸 수 있는 무료 웹앱으로 공개한다.

직접적인 계기는 아내에게 선물할 로고그램 목걸이 제작이다. 따라서 **성공 기준은 사용자 수나 기술적 우아함이 아니라, 목걸이를 받은 사람이 기뻐하는 것**이다. 이 기준에 기여하지 않는 기능은 만들지 않는다.

### 비영리 확정

광고, 수익화, 유료 기능, 굿즈 판매를 **일절 하지 않는다.** 이는 결정 사항이며 재검토하지 않는다. 이 결정이 설계에 미치는 영향:

- 런타임 비용을 0에 가깝게 유지해야 한다 → 정적 사이트 + 서버리스 함수 1개
- Wolfram 자료의 CC BY-NC 조건이 자동 충족된다
- 저작권 위험이 실질적으로 소멸한다 (5절 참조)

## 2. 배경 조사 결과

설계 판단의 근거가 된 사실들이다. 추측과 확인된 사실을 구분해 적는다.

### 2.1 원작자

- **로고그램 디자인: Martine Bertrand.** 화가이며, 프로덕션 디자이너 Patrice Vermette의 배우자. 여러 디자이너·언어학자를 섭외하려다 실패한 Vermette가 최종적으로 의뢰했다. 손으로 그린 잉크 작업이다.
- **언어학 자문: Jessica Coon** (맥길대 언어학과).
- **Stephen & Christopher Wolfram: 창작자가 아니라 분석자.** 이미 완성된 로고그램을 Wolfram Language로 분석하고, 영화 화면에 등장하는 "분석 UI"를 구현했다. 언어를 만들지 않았다.

### 2.2 공개 자료의 실태

| 항목 | 실제 |
|---|---|
| 영화에 사용된 로고그램 | **71개** (제작진은 100개 이상 제작) |
| 공개된 것 | **38개** — `WolframResearch/Arrival-Movie-Live-Coding` 의 `ScriptLogoJpegs/` |
| 공개 형식 | **래스터 JPEG.** 벡터·획 데이터·좌표 없음 |
| 의미 정보 | 파일명에 인코딩 (`OfferWeapon1.jpg`, `ThereIsNoLinearTime1.jpg` 등) |
| 문법 | **존재하지 않음.** 2016년부터 팬 커뮤니티가 "100개 사전"을 찾고 있으나 미공개 |

### 2.3 알려진 규칙 조각

영화 제작진·분석자들이 언급한 것으로, 우리가 **수용**할 원작 규칙:

- 원을 **12등분**하여 분석한다
- **획 두께가 굴절(inflection)** 을 나타낸다
- **갈고리 모양이 의문문**을 표시한다
- **비슷한 의미는 비슷한 형태를 가진다** (`Louise`와 `lifeform`이 닮았다)
- 로고그램에 **회전과 반사**가 관찰된다

마지막 두 항목이 결정적이다. 이는 **의미가 연속적인 공간에 놓이고, 형태가 그 공간의 좌표를 따라간다**는 뜻이다. `binarybrainspy/alphalogo` 프로젝트가 49개 로고그램을 푸리에 공간에 넣어 보간이 매끄럽게 작동함을 보인 바 있어(성공률 80%), 이 가설은 한 차례 검증되었다.

### 2.4 선행 프로젝트

전부 조사했고, 어느 것도 우리가 만들려는 것을 만들지 않았다.

| 프로젝트 | 한계 |
|---|---|
| `platers/Logograms-GAN`, `siraben/heptapod-diffusion` | 생성적 모델. 예쁘지만 **같은 입력에 다른 출력**, 의미-형태 관계 없음 |
| `TheOriginalBob0705/heptapod-generator` | Python CLI. 웹앱 아님 |
| `MatheusCavini/...Text2Logogram` | Kaggle 노트북 |
| `binarybrainspy/alphalogo` | 인코딩 연구 파이프라인. 생성기 아님. 단 방법론이 유용 (MIT) |
| Christine Cuskley (OpenProcessing) | 기호 생성 + 원작 인용문 매칭 데모 |
| anythingtranslate.com | LLM 래퍼. 로고그램을 그리지 않음 |
| Denis Sharmanov (Behance) | UI 컨셉 목업만 |

**공통 한계:** 생성 계열은 의미가 없고, 매핑 계열은 조형이 빈약하다. **한국어 지원은 전무하다.**

## 3. 설계 원칙

이 두 개가 프로젝트의 헌법이다. 이후 모든 설계 판단은 여기서 파생된다.

### 원칙 1 — 결정성

> **같은 입력은 항상 같은 로고그램을 낳는다.**

파생 결과:

- 생성 모델(GAN·디퓨전·LLM 이미지 생성)을 렌더링에 사용하지 않는다
- 렌더러는 **순수 함수**다: `render(IR, engineVersion) → SVG`
- 유기적인 불규칙성(잉크 번짐, 붓끝 흔들림)은 난수가 아니라 **정규화된 IR의 해시를 시드로 하는 의사난수**로 만든다
- 결과적으로 URL 공유, 캐싱, 수년 후 재현이 모두 공짜로 얻어진다

**단서 조항:** 결정성은 "동일한 엔진 버전 내에서" 성립한다. 렌더 규칙을 바꾸면 과거 출력이 변한다. 따라서 `engineVersion`을 도입하고, 내보낸 SVG에 입력·IR·엔진 버전을 메타데이터로 **반드시 embed**한다. 목걸이 파일을 5년 후에 재현할 수 있어야 한다.

### 원칙 2 — 모든 획은 의미를 담당한다

> **장식을 위해 존재하는 획은 없다.** 형태의 차이는 반드시 의미의 차이에서 온다.

파생 결과:

- 개념의 위치는 **문법 역할**이 정한다. 단어 해시로 위치를 정하면 `나는 너를 사랑해`와 `너는 나를 사랑해`가 동일한 그림이 되어 이 원칙을 위반한다
- 사용자가 어느 획이 무엇을 뜻하는지 확인할 수 있어야 한다 → MVP의 "분해 보기" 기능은 이 원칙의 검증 장치다

## 4. 아키텍처

두 단계로 분리한다. 각 단계는 상대를 모른다.

```
  한국어 / 영어 입력
        │
        ▼
  ┌───────────────┐
  │  core         │   문자열 → IR
  │  (파싱·정규화) │   조사·어미·어순·언어를 벗겨냄
  └───────────────┘
        │
        ▼   IR (언어 중립 의미 표현)
        │
  ┌───────────────┐
  │  render       │   IR → SVG
  │  (기하 생성)   │   순수 함수. 언어를 모름
  └───────────────┘
        │
        ▼
   SVG · PNG · 목걸이용 벡터
```

**경계의 의미:** `core`는 SVG를 모르고, `render`는 한국어를 모른다. 따라서 새 언어(일본어 등)를 추가할 때 `render`를 건드리지 않고, 조형을 개선할 때 파서를 건드리지 않는다.

## 5. 저작권 방침

*법률 자문이 아니다.*

- 로고그램은 영화를 위해 창작된 **미술 저작물**이며 저작권은 제작사에 있다
- Wolfram 저장소는 **CC BY-NC 4.0**이나, Wolfram은 영화 이미지 자체의 권리자가 아니므로 이 라이선스가 원저작권을 해소하지 않는다
- 다만 **"원형 표의문자 체계"라는 아이디어와 스타일은 저작권 보호 대상이 아니다.** 잉크 번짐, 원형 링, 획 두께 변조를 우리 방식으로 구현하는 것은 자유다
- 비영리 무료 팬 창작물은 공정이용 방어가 비교적 강하고, 실제로 이 38개 이미지는 10년째 여러 곳에 게시되어 있으며 제작사의 조치 사례를 찾지 못했다

### 방침

1. **원본 38개 JPEG을 앱에 번들링하거나 재배포하지 않는다.** 법적 이유보다 제품 이유가 크다 — 래스터라 각인용 벡터가 나오지 않고, 고정된 38개 문장뿐이라 임의 입력에 쓸모가 없고, 애니메이션이 불가능하다. 원본은 **로컬 설계 참조 자료**로만 쓴다
2. 앱이 출력하는 모든 획은 우리가 정의한 파라메트릭 규칙에서 실시간 생성한다
3. 앱에 고지를 넣는다: 팬 창작물이며 Paramount 및 제작진과 무관함, 원 디자인은 Martine Bertrand, 분석 자료 출처는 Wolfram Research (CC BY-NC 4.0)
4. 원본과의 비교 기능을 넣을 경우, 우리 저장소에 복제하지 않고 원 저장소의 raw URL을 런타임에 참조한다

## 6. IR — 언어 중립 의미 표현

### 6.1 동일성의 기준

**의미 동일성**을 채택한다. 어순·조사·어미·언어를 모두 정규화한다.

```
나는 너를 사랑해   ┐
너를 나는 사랑해   ├─→  동일한 IR  →  동일한 로고그램
I love you       ┘
```

근거: 헵타포드 B의 핵심은 **비선형 표기법**이다. 문장을 한 번에 통째로 그리므로 시작도 끝도 없고, 따라서 "어순"이라는 개념이 존재할 수 없다. 문자열 동일성이나 어휘 동일성을 택하면 시스템 내부에 어순이 몰래 살아남아, 원형으로 배치한 인간 문자가 된다.

부수 효과: **한국어로 쓰든 영어로 쓰든 같은 목걸이가 나온다.**

### 6.2 IR 스키마

```ts
type Role =
  | '행위' | '행위수식'
  | '주체' | '주체수식'
  | '시간' | '시간수식'
  | '양상' | '정도'
  | '대상' | '대상수식'
  | '장소' | '방향';

interface Syllable {
  onset: string;   // 초성 음소 id. 빈 초성(ㅇ)은 ''
  nucleus: string; // 중성 음소 id
  coda: string;    // 종성 음소 id. 없으면 ''
}

type Constituent =
  | { kind: 'concept'; lemma: string; role: Role }        // 사전 히트
  | { kind: 'phonetic'; syllables: Syllable[]; role: Role }; // 폴백

interface IR {
  constituents: Constituent[];
  mood: 'declarative' | 'interrogative' | 'negative' | 'volitional';
  engineVersion: string;
}
```

**`mood`와 `양상` 역할의 관계.** 둘은 같은 것의 두 층이며 중복이 아니다. `mood`는 IR의 문장 수준 속성이고, `양상`은 그것이 렌더링되는 **자리**(6시 슬롯)다. 렌더러는 `mood !== 'declarative'`일 때만 6시에 표지 획을 그린다 — 의문이면 `hook`, 부정·의지면 각각의 표지 획. 파서는 `양상` 역할을 가진 `Constituent`를 직접 만들지 않는다. 이 슬롯은 오직 `mood`에서만 채워진다.

### 6.3 정규화 및 시드

시드는 **입력 문자열이 아니라 정규화된 IR의 해시**로 계산한다. 이것이 6.1의 의미 동일성을 실제로 보장하는 지점이다.

```
canonicalize(IR)  // 키 정렬, constituents를 (role, lemma) 사전순 정렬
  → JSON 직렬화
  → FNV-1a 해시
  → 렌더러 의사난수 시드
```

정렬을 거치므로 파서가 성분을 어떤 순서로 뱉어도 시드가 같다.

## 7. 어휘와 자질 체계

### 7.1 의미 자질 (8차원, 각 0..1)

| 자질 | 뜻 |
|---|---|
| `animacy` | 생물성 |
| `agency` | 행위성 — 능동적 주체가 될 수 있는 정도 |
| `concreteness` | 구상성 |
| `valence` | 정서가 (부정 0 ↔ 긍정 1) |
| `intensity` | 강도 |
| `temporality` | 시간 관련성 |
| `boundedness` | 한정성 — 셀 수 있는가 / 지속적인가 |
| `sociality` | 관계성 — 둘 이상의 참여자를 전제하는 정도 |

이 8차원이 "비슷한 의미는 비슷한 형태"(2.3)를 구현하는 공간이다. `사랑`과 `미움`은 `valence`만 반대여서 형태가 대칭적으로 갈라지고, `고양이`와 `개`는 자질이 근접해 형태가 닮는다.

### 7.2 사전 항목 스키마

```json
{
  "lemma": "사랑",
  "gloss_en": "love",
  "features": {
    "animacy": 0.10, "agency": 0.20, "concreteness": 0.15,
    "valence": 0.92, "intensity": 0.85, "temporality": 0.30,
    "boundedness": 0.20, "sociality": 0.95
  },
  "defaultRole": "행위",
  "seedGlyph": "love",
  "status": "confirmed",
  "source": "seed",
  "addedAt": "2026-09-11"
}
```

- `status`: `confirmed` | `provisional` (10.3 참조)
- `seedGlyph`: 씨앗 글리프 id 또는 `null` (8.3 참조)

### 7.3 한국어 파싱

형태소 분석기를 외부 의존성으로 들이지 않고, 조사·어미 규칙을 직접 구현한다. 브라우저에서 돌아야 하고 결정적이어야 하기 때문이다.

| 표지 | 역할 |
|---|---|
| 은/는/이/가 | 주체 |
| 을/를 | 대상 |
| 에서/에 (장소성 어휘) | 장소 |
| 에/때 (시간성 어휘) | 시간 |
| (으)로 | 방향 · 도구 |
| 용언 (어미 제거 후 기본형) | 행위 |
| 부사 | 수식 — 수식 대상에 따라 행위수식/시간수식 |
| 의문 어미 (냐/니/까/?) | `mood = interrogative` |
| 안/못/않 | `mood = negative` |

`에`의 시간/장소 중의성은 해당 어휘의 `temporality` 자질로 판별한다 (`>= 0.6`이면 시간, 아니면 장소). 사전 기반 판별이므로 결정적이다. **미등재어(음소 폴백으로 내려가는 말)에는 자질이 없으므로 `에`를 장소로 기본 처리한다** — 미등재어는 대부분 고유명사이고, 고유명사에 붙는 `에`는 장소일 가능성이 높다.

### 7.4 영어 파싱

어순(SVO)과 전치사로 역할을 추정한다. `in`/`at`(장소성 명사) → 장소, 시간 부사 → 시간, `do/does` + `?` → 의문, `not`/`never` → 부정.

## 8. 시각 문법

### 8.1 골격 — 12슬롯 섹터, 격자 비표시

링을 12등분하여 개념을 배치한다. 12분할은 2.3의 원작 분석 격자와 일치한다.

**격자는 내부 계산에만 쓰고 출력에 그리지 않는다.** 격자를 그리면 시계·나침반처럼 보이며, 영화의 유기적인 조형과 어긋난다.

### 8.2 역할 지도 — 3축 대칭

```
        12시 행위  ──────────────  6시 양상      (축 1)
         2시 주체  ──────────────  8시 대상      (축 2)
         4시 시간  ────────────── 10시 장소      (축 3)

  홀수 슬롯 = 바로 앞 짝수 슬롯의 부속
  1시 행위수식·도구 · 3시 주체수식 · 5시 시간수식
  7시 정도·강조   · 9시 대상수식 · 11시 방향·경로
```

의미상 짝인 역할을 마주보게 배치했다. 세 가지 결과:

1. **주체·대상 반전이 축 2의 180° 회전이 된다.** 2.3에서 관찰된 "회전과 반사" 성질이 규칙에서 저절로 나온다
2. **시간 ↔ 장소가 한 축이다.** 시공간을 한 축으로 묶는 것이 의미상 옳고, 영화 주제와도 맞는다
3. **홀수 슬롯에 확장 규칙이 있다.** 비워두는 것보다 확장이 쉽다. "영원히"는 5시(시간수식)에 붙는다

빈 슬롯은 그냥 비워둔다. 그 결과 **밀도가 정보량이 된다** — `사랑` 한 단어는 링 + 획 하나로 단순하고, 긴 문장은 촘촘해진다. 목걸이 관점에서 중요한데, **짧은 입력이 오히려 예쁘다.**

### 8.3 획 생성 — 씨앗 글리프 + 자질 공간 보간

순수하게 자질에서 기하를 유도하면(자동 생성) 일관되지만 기계적으로 보일 위험이 있다. 전부 수작업으로 그리면(수작업 사전) 예쁘지만 자가학습 사전과 근본적으로 충돌한다 — LLM이 새 단어를 등재해도 그릴 획이 없다.

**채택안:** 영화 38개를 분석해 핵심 어휘 100개 안팎의 **씨앗 글리프**를 직접 디자인하고, 씨앗이 없는 단어는 자질 공간에서 가까운 씨앗들을 **보간해 합성**한다. 영화의 조형 감각이 씨앗을 통해 전체로 퍼지고, 확장성은 유지된다.

이것이 프로젝트에서 가장 노동집약적인 작업이며, 결과물 품질을 지배한다.

### 8.4 자질 → 기하 사상

| 의미 자질 | 기하 파라미터 |
|---|---|
| `agency`, `sociality` | 획의 분기 수 |
| `valence` | 곡률 · 감김 방향 |
| `intensity` | 획의 길이 · 도달 거리 |
| `concreteness` | 기본 굵기 (추상=얇고 길게, 구상=굵고 짧게) |
| `boundedness` | 획 끝 처리 (한정=뭉친 잉크점, 비한정=페이드) |
| `temporality` | 링 굵기 변조 주파수 |
| `animacy` | 부속 고리 유무 |

**굵기 변조는 굴절(inflection)을 나타낸다** — 2.3의 원작 규칙을 그대로 수용한다.

### 8.5 획 어휘

| 이름 | 형태 |
|---|---|
| `branch` | 링에서 바깥/안쪽으로 뻗는 분기 획. 자질에 따라 부속 갈래 생성 |
| `arcHug` | 링을 따라 감기는 렌즈형 접선 호 |
| `loop` | 작은 닫힌 고리 |
| `cluster` | 음절 덩어리 (9절) |
| `hook` | 의문 표지. 6시 양상 슬롯에 부착 — 2.3의 원작 규칙 |
| `ink` | 잉크 번짐 (중심 원 + 위성 반점) |

### 8.6 링

굵기가 각도에 따라 변조되는 폐곡선. 변조 함수는 문장 전체 자질의 평균에서 유도하고, 시드 기반 고조파를 더해 손으로 그린 불규칙성을 만든다. 최소 굵기를 하한으로 클램프해 링이 끊기지 않게 한다.

## 9. 음소 폴백

### 9.1 문제

사전에 없는 말(이름·고유명사)은 음소 획으로 내려간다. 그런데 `정`과 `종`은 자모가 같고 **순서만** 다르므로, 순서를 버리면 이름을 구별할 수 없다. 한편 헵타포드 B는 비선형이므로 "읽는 방향"이 존재할 수 없다.

### 9.2 해결 — 음절 나선

**순서를 각도가 아니라 반경에 인코딩한다.** 첫 음절이 링에 붙고, 뒤로 갈수록 안쪽으로 감겨 들어간다. 링 둘레에는 방향이 생기지 않고, 순서는 "깊이"가 된다.

기각한 대안:

- **슬롯 내 미세 각도 배치** — 링 둘레에 읽는 방향이 생겨 비선형 설정을 위반한다. 6.1에서 어순을 제거한 결정이 무의미해진다
- **이름 전용 내부 링** — 이름이 여러 개면 링이 계속 늘어난다 (`루이즈와 한나` → 링 3개)

나선은 슬롯 안에서 완결되므로, 이름이 주체든 대상이든 동일한 방식으로 들어간다.

**알려진 한계:** 5음절 이상의 긴 이름은 나선이 중심까지 파고들어 답답해진다. 반경 감소폭을 음절 수에 따라 조절해 완화하되, 매우 긴 이름은 조형적으로 불리함을 수용한다.

### 9.3 음성 자질 → 기하

의미 쪽이 `의미 자질 → 기하`인 것과 **같은 방법론**을 쓴다. 음성 쪽은 `음성 자질 → 기하`.

| 음성 자질 | 기하 |
|---|---|
| 조음 방법 | 획의 **형태** — 파열음(ㄱㄷㅂ)=직선+뭉친 끝 · 마찰음(ㅅㅎ)=물결 · 비음(ㄴㅁㅇ)=닫힌 고리 · 유음(ㄹ)=긴 감김 · 파찰음(ㅈㅊ)=갈래 |
| 조음 위치 | 획의 **굵기** — 양순 → 후음 순으로 두꺼워짐 |
| 긴장성 (평/격/경) | 획의 **장력** — ㄲㅉ, ㅋㅌ은 더 굵고 날카롭게 |
| 모음 고저 | 획의 **길이** |
| 모음 전후설 | 감기는 **방향** |
| 모음 원순성 | 곁점 추가 |

표기가 아니라 **소리**를 인코딩하므로, **"루이즈"와 "Louise"가 같은 그림이 된다.** 6.1의 언어 중립성이 이름에서도 지켜진다.

한글은 음절 블록 구조(초성·중성·종성)가 있어 유리하다. 유니코드 한글 음절을 자모로 분해해 처리한다.

### 9.3.1 겹종성 — 두 자음을 다 기록한다

`ㄳ ㄵ ㄶ ㄺ ㄻ ㄼ ㄽ ㄾ ㄿ ㅀ ㅄ` 열한 개를 **첫 자음의 자질로만 채우면 안 된다.** 그러면 `갈 갉 갊 갋 갌 갍 갎 갏` 여덟 개가 같은 그림이 되고 `갑`과 `값`도 구별되지 않는다. **서로 다른 이름이 구별되지 않으므로 원칙 2 위반이다.**

"표기가 아니라 소리를 인코딩한다"는 9.3의 원칙은 **언어 간 정규화**(루이즈 = Louise)를 위한 것이며, 서로 다른 한국어 표기를 뭉개라는 뜻이 아니다. 그리고 겹종성은 모음 앞에서 두 자음이 다 실현되므로(`값이` → [갑씨]) 첫 자음만 남기는 것은 **소리에도 충실하지 않다.**

따라서 `ConsonantFeatures`에 **두 번째 자음의 자질**(위치·방법·긴장도)을 둔다. 단자음은 `null`이다. 주 자질은 표기 순서대로 첫 자음을 따르고, 두 번째 자음은 수반 표시로 그린다 — 9.5.1b의 주 표시/수반 표시 구분과 같은 구조다.

**판정하지 않는 것:** 겹종성에서 어느 자음이 실현되는지는 **어휘마다 불규칙하다** — `닭`은 ㄱ, `여덟`은 ㄹ, `밟다`는 ㅂ. 자모 단위 표로는 판정할 수 없으므로 판정하지 않고 둘 다 기록한다. 단어 수준 사전이 있어야 풀리는 문제이고, 이름을 그리는 데는 필요하지 않다.

**테스트 요구:** 자질 표에 대해 두 가지를 검사한다. **(1) 커버리지** — 분해가 낼 수 있는 모든 자모 id가 표에 실제 항목을 갖는가. **(2) 유일성** — 서로 다른 자모가 서로 다른 자질을 갖는가. 커버리지만 검사하면 이 충돌을 잡을 수 없다. 실제로 커버리지 가드는 통과한 상태에서 11개가 전부 중복이었다.

## 9.5 시각 표현 — 골격과 룩의 분리

로고그램은 조형이 본질이다. 화면에 보이는 것이 영화의 그 연기 같은 잉크가 아니라 깔끔한 벡터 도형이면, 언어 체계가 아무리 정교해도 목적을 달성하지 못한다.

따라서 렌더링을 두 층으로 나눈다.

```
IR → 기하 골격 (벡터) ─┬─→ SVG 렌더러     → 목걸이 각인 · 내보내기 · 결정성 테스트
                       └─→ 스모크 렌더러   → 화면 표시 (영화 룩 + 분사 애니메이션)
```

두 렌더러는 같은 골격을 입력으로 받는다. 골격 생성은 렌더러를 모른다.

### 9.5.1 스모크 렌더링 — SDF + 도메인 워프 fbm

영화의 로고그램은 채워진 벡터 도형이 아니라, 가장자리가 침식된 반투명 연기 덩어리다. 구성 요소는 링 형태, 노이즈로 갉아먹힌 경계, 바깥으로 흩어지는 실오라기, 층층이 다른 밀도다.

**채택 방식:** 골격을 오프스크린 텍스처에 렌더해 부호 있는 거리장(SDF)을 만들고, 도메인 워프된 프랙탈 브라운 노이즈(fbm)로 경계를 침식시킨다. WebGL 프래그먼트 셰이더 하나로 처리한다.

이 방식을 택한 이유:

1. **결정적이다.** 노이즈는 좌표와 시드의 순수 함수이므로 원칙 1이 화면 렌더링에서도 유지된다.
2. **일렁임이 따라온다.** 노이즈의 3번째 축에 시간을 넣으면 연기가 지속적으로 미묘하게 흔들린다.
3. **골격의 조악함을 덮는다.** 연기 층의 변형이 강해서 골격이 단순해도 결과물이 영화처럼 보인다. 씨앗 글리프가 완성되기 전에도 품질을 확보할 수 있다는 뜻이다.

기각한 대안:

- **Canvas 2D 파티클 스탬핑** — 구현은 쉬우나 볼류메트릭한 깊이감이 나오지 않는다
- **유체 시뮬레이션(Navier-Stokes)** — 과잉이며 결정성 보장이 어렵다

### 9.5.1a 조형 방향 — 획은 또렷하고, 분위기는 배경이 만든다

*룩 랩 반복(2026-09-11) 결과. 기준선이며 수정될 수 있다. 확정값은 `design/look-v1.json`.*

실제로 파라미터를 맞춰보니, **획 자체를 연기로 풀어 흐리게 만드는 방향은 기각됐다.** 보풀(`pFray`)과 실오라기(`pWisp`)를 0으로 끄고, 먹물은 거의 순수한 검정(`pInk` 0.01)으로 또렷하게 두는 쪽이 훨씬 좋았다. 분위기는 획을 녹여서가 아니라 **배경 안개, 주변 감광, 필름 그레인**이 만든다.

따라서 스모크 파이프라인의 역할이 바뀐다. 획을 흐리게 하는 장치가 아니라:

1. **가장자리 침식** — 획 경계를 노이즈로 찢어 붓 자국처럼 만든다 (유지)
2. **내부 농담과 결** — 획 안에 짙은 심과 옅은 구멍을 만든다 (유지)
3. **연기 기둥** — 몇 군데에서만 멀리 뻗는다 (약하게 유지, `pPlume` 0.33)
4. **먹물 일렁임** — 마스크를 읽는 좌표를 아주 약하게 워프해 획 전체가 숨 쉬게 한다 (신규)

4번이 중요하다. 내부 농담만 시간에 따라 변하면 윤곽이 고정돼 "연기가 획 위를 지나가는" 것처럼 보인다. 좌표 자체를 워프하면 **먹물이 물속에서 미세하게 흔들리는** 느낌이 된다.

### 9.5.1b 획 어휘 — 복잡함의 구성 요소

단어 하나를 입력해도 기본적으로 복잡한 로고그램이 나와야 한다. 획 하나를 링에 얇게 붙이면 바퀴살처럼 보이며, 그건 목표한 조형이 아니다.

참고 자료(영화 스틸, 먹물 원 이미지)를 분해해 얻은 요소들이다. 이것이 **8.5 획 어휘를 대체한다** — 8.5의 얇은 `branch`는 폐기한다.

| 요소 | 정의 |
|---|---|
| **쓸기 덩어리** | 링을 따라 쓸고 지나가는 거대한 쐐기. 밖으로 뻗는 돌기가 아니다. **바퀴살 느낌과 서예 느낌을 갈라놓는 핵심 요소** |
| **스플래터** | 먹이 뭉친 지점에서 방사되는 가시와 떨어진 반점. 복잡함의 대부분이 여기서 온다 |
| **드라이브러시** | 붓이 마르며 갈라진 평행 줄무늬 |
| **링 끊김** | 붓이 들린 자리의 흰 틈. 참고 이미지의 링은 완전한 원이 아니다 |
| **링 겹침 호** | 여러 번 지나간 흔적 |
| **곁가지** | 획에서 갈라지는 짧은 털 |
| **뻗는 획** | 반경 방향 쐐기. 쓸기 덩어리와 병행하되 비중은 낮다 |

**원칙 2와의 관계.** 이 요소들이 다 붙으면 획 하나가 수십 개의 표시를 낳는다. 원칙 2를 지키려면 층을 나눠야 한다.

- **주 표시** — 역할 슬롯에 놓이는 쓸기 덩어리와 뻗는 획. 의미 단위이며 해독 가능하다.
- **수반 표시** — 스플래터·드라이브러시·곁가지·겹침 호. **주 표시의 자질과 시드에서 결정적으로 유도**되며, 새 의미를 넣지 않고 기존 의미를 반복한다.

따라서 임의로 흩뿌린 장식은 없다. 모든 표시가 자질까지 역추적된다. 같은 단어는 항상 같은 수반 표시를 얻고, 다른 단어는 다른 수반 표시를 얻는다.

### 9.5.1c 렌더 파이프라인 — 마스크 밉맵을 거리장 대용으로

복잡한 획을 해석적 SDF로 쌓으면 픽셀당 수천 번의 거리 계산이 필요해 실시간이 불가능하다.

**채택 방식:** 골격을 실제 삼각형으로 만들어 오프스크린 마스크 텍스처에 렌더하고, 그 밉맵 단계를 부호 있는 거리 대용으로 읽는다. 획 접선은 흐린 마스크의 기울기에서 얻는다.

- 획 개수와 무관하게 셰이더 비용이 일정하다
- 해석적 SDF보다 싸고, 접선 추정도 더 안정적이다
- 골격이 삼각형이므로 SVG 렌더러와 같은 데이터(중심선 + 굵기 프로파일)를 공유한다

**굵기 떨림은 저주파여야 한다.** 점마다 독립 난수를 주면 고주파가 되어 획이 구슬처럼 울퉁불퉁해진다. 붓의 떨림은 완만하다.

### 9.5.2 분사 애니메이션

골격의 각 점에 "도착 시각"을 부여하고, 셰이더가 그 시각에 맞춰 드러낸다. 진행 선두에 난류를 강하게 주어 잉크가 뿜어져 나가는 느낌을 만든다.

**제약 — 시계 방향으로 쓸어가면 안 된다.** 그러면 6.1에서 제거한 "읽는 방향"이 애니메이션으로 되살아난다. 잉크는 **한 점에서 양방향으로 동시에 번져나가야** 한다. 물에 떨어뜨린 잉크가 퍼지는 물리이지, 문자를 쓰는 순서가 아니다.

### 9.5.3 목걸이와의 차이

각인된 금속은 연기를 가질 수 없다. 화면은 스모크 렌더러, 목걸이는 SVG 렌더러의 출력을 쓰므로 둘은 다르게 보인다. 이는 의도된 것이다.

다만 각인본이 기하학적 도형이 아니라 유기적인 것으로 읽히려면 **골격 자체의 윤곽이 불규칙해야 한다.** 이는 8.3의 씨앗 글리프 작업에서 다룬다.

## 10. 사전 시스템

### 10.1 런타임에 LLM을 호출하지 않는 것이 기본

```
입력 → 사전 조회 → 히트 → 렌더
```

평소 네트워크 호출은 0회다. 사전 JSON은 정적 사이트에 번들된다.

런타임 LLM 파싱을 기본으로 삼지 않는 이유:

1. **원칙 1이 깨진다.** temperature 0으로도 완전한 재현이 보장되지 않고, 무엇보다 모델이 버전업되면 과거 출력이 바뀐다
2. **비영리와 충돌한다.** 서버·API 키가 필요하고 사용량만큼 비용이 발생한다
3. 정적 배포가 불가능해지고 오프라인 동작을 잃는다

### 10.2 빌드타임 사전 구축

LLM을 **개발 도구**로 쓴다. 기초 어휘(목표 2,000개 규모)의 8차원 자질을 LLM으로 생성하고, 검수 후 JSON으로 굽는다. 이 파일이 앱의 유일한 어휘 소스다.

### 10.3 런타임 메모이제이션 — 자가 성장

사전에 없는 단어가 들어오면 **평생 한 번** LLM에 묻고 결과를 영구 기록한다.

```
입력 "고양이"
  → 사전 조회 → 미스
  → 서버리스 함수 → LLM 1회 해석 → 자질 산출
  → 사전 JSON에 기록 (status: provisional)
  → 렌더

두 번째 요청부터는 LLM을 호출하지 않는다
```

LLM이 **런타임 의존성이 아니라 사전 편찬자**가 된다. 이미 기록된 항목은 재조회하지 않으므로 10.1의 문제 1이 발생하지 않는다.

**따라오는 성질:** LLM이 선택적 인프라가 된다. 예산이 소진되거나 백엔드가 죽어도 앱은 동작한다 — 사전에 있는 단어는 그대로 나오고, 없는 단어는 음소 폴백으로 내려간다. 시간이 지날수록 폴백 비율이 0에 수렴한다.

### 10.4 잠정 등재

LLM이 등재한 항목은 `status: provisional`로 표시하고 **즉시 사용한다.** UI에 "이 단어는 아직 잠정 해석입니다" 배지를 띄운다. 관리자가 승인하면 `confirmed`가 되고, 수정하면 그 시점에 형태가 바뀐다.

이 절충안을 택한 이유: 완전 자동 등재는 오답을 영구 박제하고(되돌리면 원칙 1이 깨진다), 검수 게이트는 새 단어가 승인 전까지 나오지 않아 사용자 경험을 해친다. 잠정 등재는 사용자를 기다리게 하지 않으면서 통제권을 유지한다. 목걸이처럼 중요한 것은 `confirmed` 단어로 만들면 된다.

### 10.5 저장과 비용 통제

- 사전 JSON을 **git 저장소에 커밋**한다. 언제 무엇이 어떻게 등재됐는지 추적·되돌리기가 가능하다
- **일일 LLM 호출 상한**을 둔다. 공개 엔드포인트이므로 자동화 남용 시 비용이 발생한다. 상한 초과 시 그날은 음소 폴백으로만 동작하고 앱은 죽지 않는다

## 11. 앱 기능

### 11.1 MVP

1. **입력 → 실시간 렌더.** 한국어/영어 단일 입력란. 입력 즉시 SVG 생성
2. **내보내기 — SVG · PNG · 목걸이용** (12절)
3. **URL 공유.** `/?t=나는+너를+사랑해`. 결정성에서 공짜로 나온다
4. **잉크 번짐 애니메이션.** 링을 따라 잉크가 퍼져나가는 영화 연출
5. **분해 보기.** 획에 포인터를 올리면 "주체 · 루이즈" 식으로 표시. **원칙 2의 검증 장치**이며, 랜덤 생성기와 우리를 구별하는 지점이다
6. **사전 브라우저.** 등재 어휘 목록과 잠정 배지
7. **고지 페이지.** 5절의 저작권 고지

### 11.2 이후

- **해독기 (로고그램 → 문장).** 역할 지도가 고정이므로 원리적으로 가능하다. 8.2를 택한 덕에 문이 열려 있다. 다만 이미지 인식이 필요해 덩어리가 크다
- **학습 모드** — 역할 지도를 가르치는 튜토리얼

### 11.3 범위 밖 (YAGNI)

- **갤러리 / 공유 피드** — 서버와 개인정보 처리가 붙는다. 무료 팬 프로젝트에 맞지 않는다
- **계정 · 로그인**
- **모든 형태의 수익화**
- **원본 38개 이미지 번들링** (5절)

## 12. 내보내기

### 12.1 화면용

- **SVG** — 벡터 원본. 입력 문자열, IR, `engineVersion`을 메타데이터로 embed (원칙 1의 단서 조항)
- **PNG** — SVG를 브라우저에서 래스터화

### 12.2 목걸이용 (MVP 필수)

목걸이용을 별도 경로로 두는 이유는 물리적 제약이다. **각인·레이저컷은 너무 얇은 획을 재현하지 못한다.** 화면에서 0.3px로 사라지는 붓끝은 실물에서 소실되거나 반대로 뭉친다.

목걸이용 내보내기가 하는 일:

1. **최소 선폭 보정** — 설정한 하한 미만의 획 폭을 하한으로 끌어올린다
2. **열린 획을 닫힌 윤곽선으로 변환** — 절단·각인 경로는 채워진 면이 아니라 닫힌 패스여야 한다
3. **미세 요소 정리** — 하한 미만의 잉크 반점은 병합하거나 제거한다
4. **원형 펜던트 경계 미리보기** — 지정 지름 안에 들어오는지 확인

이것이 프로젝트의 실제 목적물이므로 MVP에 포함한다.

## 13. 기술 구성

### 13.1 스택

- **정적 사이트 · Vite · TypeScript · 프레임워크 없음.** 이 앱은 입력 한 칸과 그림 하나다. 프레임워크를 올릴 이유가 없고, 오히려 **렌더러를 순수 함수로 유지**하는 것이 중요하다 — `render(IR) → SVG 문자열`이면 Node에서도 실행되어 테스트·일괄 생성·목걸이 파일 추출에 그대로 재사용된다
- **SVG 우선.** 각인용 벡터가 목적이므로 Canvas가 아니다
- **GitHub Pages 배포.** 사전 JSON 번들 포함
- **Cloudflare Workers 함수 1개** — 사전 미스 처리 (10.3)

### 13.2 모듈 경계

```
core/
  ir.ts          IR 타입 · 정규화 · 시드 계산
  parse-ko.ts    한국어 → IR
  parse-en.ts    영어 → IR
  lexicon.ts     사전 조회
  phonology.ts   자모/음소 → 음성 자질

render/
  geometry.ts    기하 프리미티브 (베지어, 테이퍼, 링)
  strokes.ts     획 어휘 (branch, arcHug, loop, cluster, hook, ink)
  compose.ts     IR + 역할 지도 → SVG
  export.ts      SVG · PNG · 목걸이용 변환

ui/              얇은 UI 계층
worker/          사전 미스 처리 서버리스 함수
tools/           빌드타임 사전 생성 · 영화 38개 분석 · 씨앗 글리프 작업
data/
  lexicon.json   사전 (git 버전 관리)
  seeds/         씨앗 글리프 정의
```

각 모듈의 책임:

| 모듈 | 무엇을 하는가 | 무엇에 의존하는가 |
|---|---|---|
| `core/*` | 문자열 → IR | `data/lexicon.json`. **SVG를 모른다** |
| `render/*` | IR → SVG | `data/seeds/`. **언어를 모른다** |
| `ui/*` | 입력 수집, 결과 표시 | `core`, `render` |
| `worker/*` | 사전 미스 시 LLM 조회·기록 | LLM API, git |
| `tools/*` | 개발 시에만 실행 | LLM API, 원본 참조 자료 (로컬) |

## 14. 테스트 전략

| 테스트 | 목적 |
|---|---|
| **결정성 테스트** | `같은 입력 → 같은 SVG 해시`. CI에서 검증. **이것이 깨지면 원칙 1이 깨진 것이므로 가장 중요하다** |
| **의미 동일성 테스트** | `나는 너를 사랑해` == `너를 나는 사랑해` == `I love you` 의 IR과 출력이 동일함 |
| **역할 구별 테스트** | `나는 너를 사랑해` != `너는 나를 사랑해` (원칙 2) |
| **골든 파일 테스트** | 대표 입력 집합의 SVG를 고정. 의도치 않은 조형 변화를 잡는다 |
| **파서 단위 테스트** | 조사·어미별 역할 추정, 의문/부정 검출 |
| **목걸이 내보내기 테스트** | 출력 SVG의 모든 획 폭이 하한 이상, 모든 패스가 닫혀 있음 |

렌더러가 순수 함수이므로 전부 Node에서 브라우저 없이 실행된다.

## 15. 미결 사항

구현 계획 단계에서 확정할 것들. 설계를 막지 않는다.

- **씨앗 글리프 개수** — 100개를 목표로 하되, 38개 원본에서 실제로 추출 가능한 조형 어휘 양에 따라 조정
- **초기 사전 규모** — 2,000개를 목표로 하되 빌드타임 생성 품질을 보고 결정
- **LLM 모델 선택과 일일 상한 수치**
- **조형 파라미터 미세 조정** — 기준선은 `design/look-v1.json`에 기록했고 9.5.1a에 방향을 정리했다. 수치는 더 바뀔 수 있다
- **씨앗 글리프와의 관계** — 9.5.1b의 획 어휘가 절차적으로 생성되는데, 8.3의 씨앗 글리프가 여기에 어떻게 얹힐지는 미정. 씨앗이 쓸기 덩어리의 중심선을 제공하는 형태가 될 가능성이 높다
- **분사 애니메이션 지속 시간** — 9.5.2의 양방향 확산 제약과 선두 난류 방식은 확정
- **목걸이 최소 선폭 하한값** — 실제 제작소의 공정에 맞춰 결정
