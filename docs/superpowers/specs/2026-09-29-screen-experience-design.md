# 화면 경험 — 연기 렌더러, 받는 순간, 헵타포드 A 소리

*2026-09-29. 계획 IV(스모크 렌더러)와 웹 화면 재설계를 한 흐름으로 묶는다. 상위 설계는 `2026-09-11-heptapod-b-design.md` (특히 9.5절).*

## 1. 목적

링크를 받은 사람이 영화 《컨택트》의 그 방에 들어온 것처럼 느끼게 한다. 로고그램이 먹처럼 번져 나오고, 헵타포드 A 같은 울림이 들리고, 눌러서 뜻을 해독한다.

성공 기준은 기능이 아니라 반응이다 — 받는 사람이 "와" 한다.

## 2. 결정 요약

| 항목 | 결정 |
|---|---|
| 주인공 순간 | **받는 순간.** 공유 링크를 연 사람이 보는 장면이 중심이다 |
| 뜻 공개 | **해독해야 드러난다.** 누르면 낱말별 획이 하나씩 빛나며 낱말이 뜨고, 마지막에 문장 전체 |
| 소리 | **헵타포드 A 느낌을 새로 합성.** 뜻은 담지 않지만 같은 문장이면 같은 소리 |
| 시작 | **누르면 시작.** 받는 화면은 '눌러서 시작' 하나만 보인다 (브라우저 자동재생 제한도 이 누름으로 풀린다) |
| 화면 톤 | **영화 그대로.** 어두운 방, 가운데 뿌옇게 빛나는 하얀 유리벽, 그 위의 검은 먹 |
| 만드는 화면 | **같은 방에서.** 아래 입력줄 한 줄, 쓰면 바로 번진다. 부가 기능은 '자세히' 안에 |
| 구현 방식 | 룩랩의 WebGL2 셰이더를 웹앱 모듈로 옮긴다. 소리는 WebAudio 직접 합성. 라이브러리 없음 |
| 대비책 | WebGL2 가 없으면 지금의 SVG 를 그대로 보여 준다. 그 밖의 대비책은 두지 않는다 |

**지켜야 할 선:** 영화의 장면 이미지·로고·포스터·음원·전용 글꼴을 쓰지 않는다. 분위기는 새로 그리고 새로 합성한다. 팬 창작물 고지는 유지한다.

## 3. 경험의 흐름

### 3.1 받는 사람 — 주소에 `#t=` 가 있을 때

1. **대기.** 어두운 방, 가운데 희미하게 빛나는 유리벽. 가운데에 '눌러서 시작' 만 작게.
2. **번짐.** 누르면 헵타포드 A 울림이 시작되고, 링 위의 한 점에서 먹이 **양쪽으로 동시에** 번져 나간다. 링이 닫히고(양보문이면 닫히지 않고 지나쳐 나선으로 빠진다), 획들이 먹이 닿는 차례로 피어난다. 전체 6~8초.
3. **일렁임.** 다 번진 뒤에도 먹은 물속처럼 미세하게 흔들린다 (9.5.1a 의 먹물 일렁임).
4. **해독.** 잠시 뒤 아래에 '해독하기' 가 희미하게 뜬다. 누르면 낱말별 획 묶음이 하나씩 빛나고 그때마다 그 낱말이 떠오른다. 마지막에 원래 문장 전체가 나타난다.
5. **나도 만들기.** 맨 아래 작게. 누르면 주소의 `#t=` 를 지우고 만드는 화면이 된다.

### 3.2 만드는 사람 — 주소에 `#t=` 가 없을 때

1. 같은 방. 화면 아래 얇은 입력줄 한 줄.
2. 문장을 쓰고 엔터 → 유리벽에 먹이 번진다. 입력이 이미 누름이므로 '눌러서 시작' 은 없고 소리도 바로 난다.
3. 아래에 '링크 보내기'. 폰이면 공유 창(`navigator.share`), 아니면 링크 복사.
4. '자세히' 를 열면 분해 보기, SVG/PNG 받기, 팬 창작물 고지. 지금 기능을 그대로 옮긴다.
5. 소리 켜기/끄기 버튼은 구석에 작게 (두 화면 공통).

휴대폰 세로 화면이 기준이다. 링크는 대부분 카카오톡 안에서 열린다.

### 3.3 해독 순서와 낱말 표시

- **순서는 먹이 닿은 차례**다 (4.1 의 도착 시각 순). 시계 방향 같은 고정 순서를 쓰면 6.1 에서 없앤 '읽는 방향' 이 되살아난다. 도착 시각은 시작점에서 양쪽으로 번지므로 좌우가 섞인다.
- **낱말은 원래 문장의 언어로** 띄운다. 한국어 문장이면 표제어, 영어 문장이면 `gloss_en`. 음소 폴백은 음절 그대로.
- 링은 해독 대상이 아니다. 문장 종류 표지(양상)는 '의문'·'부정' 처럼 이름으로 띄운다.

## 4. 구조

각 부품은 한 가지 일만 하고, 앞의 두 개는 순수 함수라 브라우저 없이 테스트한다.

| 부품 | 하는 일 | 위치 |
|---|---|---|
| 번짐 시간표 | 획마다 도착 시각과 해독 묶음 번호를 계산 | `src/render/arrival.ts` |
| 발화 악보 | 문장 → 헵타포드 A 발화의 음표 목록 | `web/voice/score.ts` |
| 연기 렌더러 | 룩랩 셰이더 이식. 시각 `t` 와 강조 묶음을 받아 그린다 | `web/smoke/` |
| 목소리 | 악보를 WebAudio 로 연주 | `web/voice/voice.ts` |
| 장면 | 받기·만들기의 진행 상태 관리 | `web/scenes/` |

`src/core` 는 `src/render` 를 모른다는 기존 규칙과, core/web 에 Node 전용 API 를 쓰지 않는다는 규칙을 그대로 따른다. 지금의 SVG 렌더러는 다운로드·목걸이·대비책에 계속 쓴다.

### 4.1 번짐 시간표 — `arrival(result, look): Arrival`

입력은 `render()` 결과(획 + 메타데이터), 출력은 획마다 `{ at: 초, part: 묶음 번호 }` 와 전체 길이.

- **시작점** θ₀ 는 IR 해시에서 얻은 시드로 정한다. 같은 문장이면 늘 같은 곳에서 번진다. 룩랩의 고정값 `pSprayAng` 은 쓰지 않는다.
- **링의 먹 선두**는 θ₀ 에서 양쪽으로 같은 속도로 간다: `t_ring(θ) = T_ring · 각거리(θ, θ₀) / π`. 링의 틈은 건너뛴다 — 시간은 흐르되 칠하지 않는다. 선두가 틈에서 멈추면 작은 틈 하나가 번짐 전체를 세운다.
- **그 밖의 획**은 뿌리 각도에 선두가 닿는 시각 + 깊이(바깥 층일수록 늦게) + 시드 기반의 작은 흔들림.
- **대칭성:** θ₀ 기준 거울 위치의 두 점은 같은 시각에 칠해진다 (흔들림 제외, 틈이 없는 자리 기준). 이것이 '쓰는 순서가 아니라 번지는 물리' 라는 9.5.2 의 제약을 코드로 고정한다.
- 묶음 번호는 `web/breakdown.ts` 의 `partKeyOf` 와 같은 규칙이다 (링은 한 묶음).

### 4.2 연기 렌더러 — `web/smoke/`

- 룩랩(`spikes/look-lab.html`)의 WebGL2 파이프라인을 옮긴다: 획을 삼각형으로 마스크 텍스처에 그리고, 밉맵을 거리 대용으로 읽어 가장자리 침식·내부 농담·먹물 일렁임을 만든다 (9.5.1c). LOD 0 을 밀도에 섞어 가시가 살아남게 하는 것도 그대로.
- 마스크 텍스처의 다른 채널에 **도착 시각**과 **묶음 번호**를 담는다. 셰이더는 `uTime` 보다 늦게 도착하는 픽셀을 감추고 선두에 난류(`pLeadTurb`, `pFrontSoft`)를 준다. 해독 중에는 `uHighlight` 묶음을 빛낸다.
- 연기 값은 `design/look-v3.json` 의 `p*` 키를 읽는다 (이미 있음).
- 방·유리벽 값(방의 어둠, 유리벽 빛의 반경·세기, 안개)은 새 파일 `design/screen.json` 에 둔다. 목걸이 룩과 키 집합을 맞출 필요가 없는 화면 전용 값이기 때문이다. 소리 값도 같은 파일에 둔다.

### 4.3 헵타포드 A 목소리 — `web/voice/`

- **`score(ir, arrival): Note[]`** — 순수 함수. IR 시드로 정해지므로 같은 문장이면 같은 악보.
  - 바탕: 아주 낮은 저음 드론 (방 전체).
  - 발화: 먹이 번지는 동안 고래 울음 같은 낮은 울림 몇 개. 음높이가 천천히 미끄러지고, 성도 공명(포먼트 필터)이 있다. 울림 개수·길이는 낱말 수와 번짐 길이에 맞춘다.
  - 해독: 낱말이 빛날 때마다 짧고 맑은 울림 하나.
- **`voice.ts`** — 악보를 WebAudio 로 연주. 넓은 방의 긴 잔향은 노이즈로 만든 임펄스 응답(파일 없음).
- 음색 값은 `design/screen.json`. 여러 버전을 들려 드리고 고르는 단계를 둔다 (6절).

### 4.4 장면 — `web/scenes/`

- `receive.ts`: 대기 → 번짐 → 일렁임 → 해독 가능 → 해독 중 → 해독 끝.
- `make.ts`: 입력 → 번짐 → 보내기 가능. '자세히' 패널.
- 렌더러와 목소리는 인터페이스로 주입한다. 테스트에서는 가짜 구현을 넣어 진행 순서만 본다.
- 모드 결정: 주소에 `#t=` 가 있으면 받기, 없으면 만들기. 기존 `web/share.ts` 의 `encodeShare`/`decodeShare` 를 그대로 쓴다.

## 5. 대비책

WebGL2 컨텍스트를 얻지 못하면 지금의 SVG 렌더러 결과를 유리벽 자리에 그대로 둔다. 해독(획 강조는 SVG `fill` 로)과 소리는 그대로 동작한다. 그 밖의 대비책(동작 줄이기 대응 등)은 두지 않는다.

## 6. 만드는 순서 — 단계마다 사용자 확인

1. **연기 렌더러 + 번짐.** 번짐 시간표, 셰이더 이식, 도착 시각 드러내기. 확인: 룩랩과 같은 먹이 웹앱에서 양쪽으로 번지는 영상.
2. **새 화면.** 어두운 방·유리벽, 받는 장면·만드는 장면, 해독, 공유, '자세히'. 확인: 폰에서 링크를 열어 처음부터 끝까지.
3. **헵타포드 A 소리.** 악보, 합성, 잔향. 확인: 몇 가지 음색을 들어 보고 고르기.

## 7. 테스트

- **번짐 시간표:** 같은 입력이면 같은 결과 / θ₀ 기준 대칭 / 시작점이 문장마다 다름 / 틈이 있어도 링 끝까지 번짐 / 바깥 층이 안쪽보다 늦음 / 묶음 번호가 `partKeyOf` 와 일치.
- **발화 악보:** 같은 입력이면 같은 악보 / 울림 수가 낱말 수를 따름 / 해독 울림이 묶음마다 하나.
- **장면:** 가짜 렌더러·목소리로 상태 전이 순서, 모드 결정(`#t=` 유무), '나도 만들기' 가 해시를 지움.
- **눈과 귀:** 셰이더와 소리는 자동 테스트로 판단할 수 없다. 6절의 단계별 확인이 그 역할이다.
- 기존 테스트(파서·렌더러·목걸이)는 바뀌지 않아야 한다. 목걸이 컷 파일은 바이트 단위로 같아야 한다.

## 8. 범위 밖

여러 문장, 목걸이 UI, 사전에 없는 말의 LLM 해석(계획 VI), 동작 줄이기 대응, 보낸 사람 이름·메시지 같은 부가 정보.
